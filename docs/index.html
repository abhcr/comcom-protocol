The exact protocol path

Known website in. Validated outcome out.

  1. 01
    Discover

    GET or HEAD RFC 9727 /.well-known/api-catalog over HTTPS.

  2. 02
    Verify

    Load the manifest and digest-verified profile release bundle.

  3. 03
    Select

    Choose an exact advertised ID, version, direction, kind, and form.

  4. 04
    Validate

    Bind sender, recipient, endpoint, security, extensions, and typed payload.

  5. 05
    Act

    Use the correlated structured result or receipt as the authoritative record.

Legacy notice: /.well-known/comcom is retained only for v0.1 compatibility. It is not an IANA-registered suffix. V0.2 uses the registered RFC 9727 api-catalog route.

Full quick start

Run one complete booking exchange.

Requires Node.js 24. The runner uses an available loopback port, fresh IDs and timestamps, HTTP, and mocked authentication. It sends no external business requests and stops its server automatically.

git clone https://github.com/abhcr/comcom-protocol.git
cd comcom-protocol
npm ci
npm run demo:v0.2

Expect five PASS lines covering discovery, a validated result, exact replay, conflict rejection, and asynchronous completion. Failures exit unsuccessfully. Follow the evaluation walkthrough.

One authoritative message, three entry paths

The booking command stays the same.

Direct automation

A buyer system discovers the provider, checks availability, and submits the exact booking command.

Generated UI

A conventional form uses schema labels, formats, constraints, and enumerations to produce that command.

AI-assisted

An edge AI gathers intent and confirmation, then submits that same command and explains its structured result.

Natural language can explain the record. It never becomes the authoritative transaction.

Product search → availability → quote → orderAppointment availability → booking → status → cancellationOffer or announcement → accepted, discarded, or duplicate receipt
