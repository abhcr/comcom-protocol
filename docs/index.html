Comcom is an open protocol for two or more businesses or organisations that frequently interact. It defines shared formats for their systems to exchange requests, responses, and status updates.

What, why, and howSee the purchase-order example

After accepting the purchase order, the manufacturer’s configured automation starts its internal manufacturing workflow. The trader can request status through Comcom. Illustrative workflow, not a live service.

What is it?An open-source protocol for inter-business communication. Developers or integration partners connect the businesses’ existing systems; operations teams use the resulting workflows.
Why does it matter?Repeated orders, enquiries, and status checks often involve emails, manual entry, or custom integrations. Shared request and response formats aim to reduce that repeated work across partners.
How does it work?Partners agree on a workflow and implement the relevant capabilities. Their systems exchange authorised requests and structured results, while each business keeps its own internal processes.

The exact protocol path

How systems exchange a request.

  1. 01
    Discover

    GET or HEAD RFC 9727 /.well-known/api-catalog over HTTPS.

  2. 02
    Verify

    Load the manifest and digest-verified profile release bundle.

  3. 03
    Select

    Choose an exact advertised ID, version, direction, kind, and form.

  4. 04
    Validate

    Bind sender, recipient, endpoint, security, extensions, and typed payload.

  5. 05
    Act

    Use the correlated structured result or receipt as the authoritative record.

Example: trader and manufacturer

A purchase order starts a manufacturing workflow.

A trader and a manufacturer agree to partner and automate a recurring order process. Each connects its own software to the agreed Comcom capabilities and authorises the other business to use them.

  1. 01
    Agree and connect

    Both partners agree on products, order details, permissions, and acceptance rules. Developers connect their separate systems.

  2. 02
    Send the purchase order

    The trader’s software sends PO-1042 for 500 steel brackets to the manufacturer’s software using Comcom.

  3. 03
    Check and accept

    The manufacturer’s software validates the request and applies its own commercial and capacity checks.

  4. 04
    Start manufacturing

    Once the order is accepted, the manufacturer’s configured automation creates an internal production job and schedules the work.

  5. 05
    Return status

    The trader’s software requests order status through Comcom. The manufacturer returns the agreed status from its system.

Comcom is the shared language between the businesses. The manufacturer implements the link from an accepted order to its manufacturing workflow; each partner keeps control of its own system.

Inspect the Comcom purchase-order messages

Illustrative document snapshots using the existing draft comcom.order.create capability. The result confirms creation of a proposed order, not completion of manufacturing.
