# Advisory: Comcom v0.1 semantic and security limitations

Comcom v0.1.0 is an experimental prototype, not a production-ready or globally interoperable protocol release.

The review that initiated v0.2 identified material limitations:

- many capabilities shared generic schemas and incomplete lifecycle semantics;
- request validation did not bind message kind, manifest direction, transport identity, recipient, and response correlation tightly enough;
- discovery did not provide an SSRF-safe HTTPS resolution algorithm;
- idempotency did not use a canonical semantic projection;
- the security declaration was not faithful to OpenAPI Security Scheme and Security Requirement semantics;
- conformance relied on one implementation and schema-derived fixtures;
- release artifacts did not have a frozen digest manifest.

Do not use v0.1 for transactions, authorization decisions, untrusted URL retrieval, or production interoperability. Its `/.well-known/comcom` discovery name is not IANA-registered and is retained only as a compatibility route. The breaking v0.2 line uses RFC 9727 `/.well-known/api-catalog`, closed capability profiles, independent Node and Python validators, and evidence-gated maturity.
